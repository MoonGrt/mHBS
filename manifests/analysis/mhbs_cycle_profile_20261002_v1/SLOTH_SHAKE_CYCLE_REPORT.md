# SLH-DSA-SHAKE 周期分析报告

生成日期：2026-10-02 15:24 +08。

## 测量配置与口径

- 编译器：`/media/sk1/25700d07-be6e-4225-bd06-13baa4403116/Vivado/ascon-sign/tools/cva6/toolchain/bin/riscv-none-elf-gcc`；GCC 13.1.0；`-O2 -march=rv32imc -mabi=ilp32`。
- 运行环境：本项目 `pug_rv32` CPU、默认未掩码 Keccak 加速器、Verilator RTL 仿真。
- 样本：每组参数的首个 KAT 向量，消息长度 33 字节；正常验签计入数据，翻转位验签只用于正确性检查。
- 正确性：所有所选参数的密钥和签名校验、正常验签、翻转位拒绝测试均通过。
- 边界：从 `slh_keygen`、`slh_sign`、`slh_verify` 函数入口周期开始，到返回地址执行前结束；不含测试框架和校验码计算。
- 哈希运行：Keccak 轮次或内部链迭代实际执行的周期；与 CPU 轮询重叠时优先计入此类。
- 通讯：其余周期中 Keccak MMIO 事务占用总线的周期。
- 哈希输入构建：总周期减去上述两类；此列还包含树遍历、普通内存访问、随机数处理和算法控制，**不能单独解释为纯粹的输入拼接耗时**。
- 采集方式：各参数集使用独立固件和仿真进程，并发上限 `6`；并发不会改变单次操作的周期。

## 主要发现

- keygen 最长的是 SHAKE-192s：18,276,682 周期；最大类别：Keccak 运行（占 57.89%）。
- sign 最长的是 SHAKE-256s：294,299,439 周期；最大类别：哈希输入构建及其他 CPU 工作（占 61.77%）。
- verify 最长的是 SHAKE-256f：856,681 周期；最大类别：哈希输入构建及其他 CPU 工作（占 63.26%）。
- 六组 keygen 均以 Keccak 运行占比最高，占 50.59%–63.84%。若加速器周期固定，优化 CPU 路径的收益受这一占比限制。
- 六组 verify 的剩余 CPU/内存类周期占 57.50%–66.16%；进一步定位应细分树遍历、地址处理及内存访问，不能仅凭本列认定输入拼接是瓶颈。
- 通讯占比最高的是 SHAKE-256s sign，为 10.10%。单独优化 MMIO 的理论收益有限；签名中的剩余 CPU/内存类周期随参数集增大更值得细分。
- SHAKE-128f sign 本次计得 4,943,102 周期，与此前同工具链函数入口至返回测量的 4,943,102 周期相差 +0 周期。固件内 `[CLK]` 读计时器的边界还包含调用与读时钟开销，本次其值为 4,943,111 周期。

各行三类周期严格互斥且相加等于总周期。哈希运行周期表示加速器实际推进的时钟，其间 CPU 可能在轮询；它不是可以从总周期直接扣除的独立 CPU 工作量。

## 复现

```bash
python3 flow/profile_shake.py --params 128s 128f 192s 192f 256s 256f
python3 flow/profile_shake.py --params 128s 128f --jobs 2
```

单组构建及仿真日志位于 `.shake_profile/<参数集>/`，Verilator 构建日志位于 `.shake_profile/rtl/`。脚本只有在所选参数的 KAT 与周期检查全部通过后才写报告。
