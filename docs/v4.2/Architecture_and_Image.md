# μHBS v4.2：共同硬件与独立操作

工程版本 v4.2；物理格式 `slh64_v4.2`，布局修订号 2；五类宏操作沿用 ABI 4 语义。
旧 ABI 4 镜像不能直接装入新硬件。格式检查仅在离线工具进行，RTL 信任已生成镜像。

## 输入、运行和输出

唯一顶层 `mhbs_top`，输入仅 `clk/rst`。rst 高有效，异步置位、同步释放。
每次复位装载 descriptor 0/1、program 控制字及五个节点槽，然后从指定入口运行一次。
控制字选择 Keygen 或 Sign，完成后停机。Keygen 输出 SK||PK；Sign 输出完整签名。
Sign 公钥根从镜像装载，不依赖上次运行。Boot、操作周期分别计数，未运行的操作计数为零。
三参数点、两操作共享同一硬件；六份检查点仅初始化内容不同。

## 固定布局

| ROM | 容量 | 读端口 |
|---|---|---|
| program | 64×64 | 1，异步读 |
| template | 16×64 | 1，异步读 |
| descriptor | 32×64 | 2，异步读 |

program 0–31 存指令；32–35 secret seed；36–39 secret PRF；40–43 public seed；
44–47 randomizer；48–51 public root；52 控制；53–63 消息（最多 87 字节）。
每个节点槽固定 32 字节，按低位字节到高位字节存放，不足部分为零。
控制字 bit0 为 Sign，bits5:1 为入口，bits12:6 为消息字节数。Keygen 消息长度为零，public root 槽也为零；根必须由该次 Keygen 计算产生。

SINGLE/RUN：bits63:62 为类型 0/1；61:58 为模板；57:47 为 layer/group 坐标；
46:41 为发射次数减一；40:30 为坐标步长。坐标高 5 位为 layer，低 6 位为 group。
LOOP：类型 2；61:57 为回跳数减一；56:51 为额外重复次数；50:40 为坐标增量。
HALT：类型 3，其余零。支持两层 LOOP。所有指令的其余位为零。

Template bits2:0 为 HASH/CHAIN/TREE/TRANSFORM/EMIT（1–5）；7:3 为主 descriptor；
12:8 为结果路由（零表示不路由）；15:13 分别为 CAPTURE、AUTH、EXTERNAL_ROOT。
其余零。只有一个未完成宏，下一条等待整条宏完成；宏内部仍并行使用两个 Hash 上下文。

Descriptor 固定连续映射定义在 `model/slh64.py` 的 ADDRESSES 中，跨参数和操作相同。
物理记录删除高 4 位 kind；离线工具根据固定槽类型复原逻辑类型并验证引用。
引用值改为 5 位物理地址，原 8 位字段的高 3 位为零。其他有效配方/路由字段保持逻辑位置。
Descriptor 0 仅保留两项 18 位输出长度；descriptor 1 仅存参数集编号 0/1/2，分别表示 128f/192f/256f。
其余位为零；核将编号译为 n=16/24/32、FORS a=6/8/9、子树高度 3/3/4。
不再暴露不受支持的参数交叉组合。各 Hash 配方、输出长度及路由仍由其他 descriptor 决定。
链归约仅保留 SLH 列表 Hash；单链直通也保留。离线拒绝 L-tree 成对归约及额外 leaf Hash。
早期候选的布局修订号为 1，须使用其快照内配套镜像和 RTL，不能混用。
索引、identifier、树缓存模式、第二命令槽和多事件调度均不参与生产接口。

## 综合边界

顶层直接声明数组并 `$readmemh`，执行核单独综合，真实镜像不进入执行核常量传播。
ROM 壳使用与算法无关的构建数据综合，所有有效输出位须依赖所有地址位。
综合后从 LUT 输入引脚连接导出地址排列，与构建数据的每个地址逐位核对，随后生成六组 INIT。
推断单元可以是 LUT ROM，不把 LUT as Logic 错记为 LUTRAM。面积包含所有 ROM、装载和统计逻辑。

## 软件先行记录

`software_gate.json` 核验六组完整输出、KAT、独立 Keygen 根、既有宏执行器的完整 Hash 轨迹和计数。
独立算法签名实现可能重复部分链计算，因此不强求其原始 Hash 次数等于优化宏执行器；共同树节点值需一致。
`rtl_start.json` 保存软件门禁哈希和开始 RTL 修改前的全部生产源码哈希。

当前文档描述实现接口，不代表布线性能验收已经完成。
