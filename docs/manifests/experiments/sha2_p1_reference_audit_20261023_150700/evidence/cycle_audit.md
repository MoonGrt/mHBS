# SHA2 P1U1 SLH-DSA-128f Sign 周期审计

当前 RTL 与最新矩阵冻结的全部生产 RTL 校验一致。仅在独立测试台增加观察端口，未修改生产 RTL，未综合或布线。

- 完整 Sign 实测：15,192,941 周期；104,925 次 SHA256；211,432 次 compression。
- 输出和签名缓存的全部 17,088 字节均与现有 expected.mem 一致。签名 SHA256：`7d620e77679ba029c2783b4a8345dffbe7fae5c4d04aff4bb9d50b7df509fae1`。
- 每次 compression 从接受输入到返回结果固定 65 周期：64 轮 + feed-forward。合计 13,743,080 周期；其他调度、块格式化、执行控制共 1,449,861 周期。
- 104,920 次哈希重复完全相同的 `PUB.seed || 0^48` 首块：PRF 8,272 次，节点 F/H 96,472 次，列表 T 176 次。此首块本身耗费 6,819,800 周期，占总计 44.89%。
- 若一个 Job 缓存一次该首块 CV，compression 工作量可由 211,432 降至 106,513；64 轮本身下界变为 6,816,832 周期。这是工作量理论值，不是候选 RTL 实测周期。
- SLOTH `drv/sloth_sha2.c:591-608` 明确预计算并保存 SHA256 公共种子 CV，`sha256_chain_16` 在 634-636 行触发整链。当前 RTL 在 `rtl/hash/sha2-recipe.sv:758-760` 每个新哈希都重设 IV/block=0，550 行构造相同首块，并未缓存其 CV。
- SHAKE P1U1 同矩阵为 2,619,846 周期、105,641 次 Keccak；不能直接假定 SHA256 与 Keccak 的每调用成本相同：SHA256 此处为 64 轮/块，SHAKE 为 24 轮/置换。

现有测试 `tb/fast_main.cpp:40-43` 核对输出每字节，69-82 行核对签名缓存每字节，63-66 行核对工作计数。向量生成 `model/vectors.py:51-58` 使用本项目 Machine，60-67 行使用独立 Python verifier；本周期审计本身不构成对外部 slhdsa-c 的逐字节交叉验证。外部 C 交叉验证由主任务独立执行。
