# 批量响应控制路径优化

本轮在 `executor` 内将批量响应限定为 `pipe_mode && pipe_response_valid_raw`，目标是让标量配方译码退出“响应 → 空槽选择 → 请求 ready → 状态更新”组合路径。未新增寄存器或流水级。同口径综合已完成，此候选未取得净收益，已撤回限定逻辑；测量结果见 [100 MHz 诊断报告](Timing_Diagnostic_20261019_103518.md)。

## 修改依据

上一轮 `timing_diagnostic_20261019_101429` 的 P12U1、50 ns 约束综合中，数据路径由 7.008 ns 降至 6.730 ns，等效面积由 15,615.250 降至 15,463.375 Slice。残留最长路径从 `task_recipe_reg[58]` 到 `batch_issue_phase_reg/CE`，标量请求分类仍影响批量返回和滚动槽选择。

本轮保留 recipe 对外握手，只在执行器内部限定响应的使用范围。批量模式下，`scalar_bridge = bridge_response || (!batch_mode && scalar_request)` 可化简为 `bridge_response`；显式加入批量模式条件后，综合器可消除上述路径对当前标量请求译码的依赖。该效果仍须查看新网表确认。

静态审查覆盖全部 11 类使用点：它们已有批量阶段限定，或在非批量分支中不使用该响应值。P1 仍采用标量执行路径。审查依赖正常可达状态及已有阶段标志一致性断言，不声明任意强制破坏状态下的形式等价。
