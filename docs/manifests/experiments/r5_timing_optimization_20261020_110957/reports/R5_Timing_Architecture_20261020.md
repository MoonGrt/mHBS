# R5 基础 SHAKE 时序架构优化

本轮以冻结 R5（20261020_100441）为唯一比较基线：它是上一轮唯一让 P12U1／P4U1 都闭合约130MHz的同一份RTL。旧R1在P4U1同频率下的面积与ATP更低，仍作为历史对照；选择R5不代表它在每个P/U点均胜出。

当前工作区为S4。S1与S4已启动同一冻结源码的固定目标布线，其余实际频率与ATP结论待完成；[实时对照](../../r5_timing_optimization_20261020_110128/reports/R5_Timing_Progress_20261020.md)持续更新。

## 实际瓶颈与处理

R5在150MHz下，P12最差路径是寄存读地址经过相邻地址运算、端点RAM及流式字选择到fetched_source：7.809ns、9级，约82.1%在线路上；P4最差路径由node_level经认证条件选择进入端点RAM，约7.012ns、12级。R5在130MHz下还有held_tag经响应仲裁再进入capture RAM和held_capture的7.633ns路径。没有把这些失败WNS换算为已验证的较低频率。

- S1：只保留流式prefix中确实会消费的端点字。有效source7仅为24字节节点在position48的第二个64位字，索引恒为0；LMS的prefix literal仅需firstnode[79:0]。后续列表仍走原128位窗口，删除的高字动态选择不参与有效输出。
- S1：独立awaiting_response位图记录“完成但尚未发布”，发布时清位，complete/busy仍消费后才释放，切断held_tag译码→优先编码→RAM地址的反馈。等价断言检查它始终等于complete去掉已发布槽。
- S1：target_at_level与node_index一同装载、上移，认证匹配和父节点跳过使用当前层坐标，去掉逐次可变移位。
- S2：主／邻读地址同拍登记；认证匹配与树高资格随节点产生边沿登记。该步骤把读路径运算前移，但P12的新最差路径变成复杂地址选择后再加一，诊断出现回退，未作为首选布线候选。
- S3：recipe六阶段控制显式使用one-hot编码。综合日志确认从sequential改变为one-hot；它降低了一部分译码，但没有独自消除选择器后的加一链，保留中间结果。
- S4：各候选输入先计算地址对，主／邻地址并行选择，再在原边沿登记；常量、偶数波和LT奇数尾分别化简，保留127→126保护。将总选择器后的串行加一移走，不增加状态周期。

全部改动适用于合法P/U，P1仍保留标量执行，单Hash lane、外部数据接口及完整认证路径重算不变。没有新增false-path/multicycle或关闭时序优化。

## 已出现的实际布线结果

S1的P4U1在7.143ns下完整布通并通过STA：实际约139.9972MHz，WNS +0.068ns、WHS +0.094ns，DRC=0；布线面积9,745.625等效Slice。名义140MHz因周期量化未达到严格数值，实际频率按工具约束报告。三个Sign的布线ATP较R5@130MHz均降低10.662%，较旧R1@130MHz分别降低5.974%／5.995%／5.983%（SLH／XMSS／LMS）。这是S1的独立证据，不能转用为S4的已闭合频率。详细来源绑定与计算见 `analysis_evidence/S1_EARLY_STA.json`。

## 布线与交付

S1：P12/P4各150／140MHz，共4项；S4：P12/P4各150／140／135MHz，共6项。每项独立综合、布局布线和STA，源自相同冻结候选及一致工具设置；最多12个Vivado、每个2线程。异常综合超过10分钟仅延后分析，进程继续。

只有源码／工作量匹配、完整布通、DRC无错误且setup/hold通过，才报告实际约束周期对应的频率和布线ATP；名义目标的周期量化单独标注。低频综合路径不反推Fmax，未完成项留空。结论适用于common OOC内部受约束路径。
