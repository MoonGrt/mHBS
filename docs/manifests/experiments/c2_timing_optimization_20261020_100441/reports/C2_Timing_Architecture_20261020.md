# C2 后续 SHAKE 时序架构优化

本轮唯一比较基线为冻结 C2（20261019_211601），不使用旧 B0 或 C7 代替。当前工作区为 R5；R1 与 R5 正在做 P12U1／P4U1 的名义 150／130 MHz 固定目标布线，尚未选定实际频率或 ATP 胜出者。动态结果见[后台总对照](../../c2_timing_optimization_20261020_100009/reports/C2_Timing_Progress_20261020.md)。

## 路径与改动

C2 的实际布线最差路径已从 Keccak 轮函数转为控制选择、异步上下文 RAM 和端点写回，线路延迟占约八成。P12 的 lane_request_active 经标量请求译码、上下文读标签进入 key/digest RAM，再写端点；P4 还存在端点 RAM 经流式窗口选择及 padding 到暂存器的路径。

- R1：读标签仅由已接受标量请求或已登记消费阶段选择，防止新请求译码影响返回数据。
- R2：在已有响应发布边沿同步锁存 digest/capture 与 tag，直接端点写回从这些寄存器起步；有序捕获仍保留原异步读口。无额外响应周期，停顿时 payload/tag 一起保持。
- R3：固定引擎模式由已接受请求所有权决定，保留 C2 的 1600 位弹性 launch 级和上下文数据预读。
- R4：在已有链设置阶段登记 FORS 相对索引；128 位窗口与 padding 之间增加弹性一级。P4 的 FORS 长算术路径退出最差路径，但 P12 仍受剩余握手选择链影响，因此未直接选为最终候选。
- R5：响应 valid/ready 全部按已接受请求归属，切断未接受 recipe 到退槽、选槽、ready 的反馈；校验和直接读取 transform_index 指向的消息 nibble，将 15−digit 化为明确的 4 位取反再扩为 12 位累加，去掉状态/链索引/校验数字选择和第二段算术。

所有改动保持通用 P/U；P1 继续独立标量执行。模块端口和单 Hash lane 数量不变，未新增时序例外。

## 后台布线与证据边界

R1、R5 各四项固定目标任务已启动；C2 参考只新增两项 130 MHz 布线，六项 Sign 与 100 MHz 诊断严格复用精确匹配的历史实测证据。长任务继续后台运行，异常耗时只延后分析。全机最多十二个 Vivado，每个两线程。

频率和 ATP 只对布通、DRC 无错误、setup/hold 均通过的共同核内部受约束路径报告。名义 150 MHz 约束在工具中若量化成 6.667 ns，实际应报告约 149.9925 MHz；不得把未通过 WNS 外推为 Fmax。布线尚未完成的条目保持待验证，不代表整板或顶层接口频率。

冻结 RTL、源码 SHA、每阶段相对 C2 补丁及综合分层/时序/日志均归档；历史快照不由当前源码替换。
