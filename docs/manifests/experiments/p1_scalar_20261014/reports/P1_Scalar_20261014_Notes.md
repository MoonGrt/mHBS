## 实现范围

用户在 recipe 合并后明确要求 P1 恢复标量执行，本轮基线为统一上下文版本 `20261014_143751`，不再把其 P1 周期作为必须逐拍相同的前提。P1U1/P1U2 完整重新测量；P4U1/P12U1 作为多槽兼容与综合对照。未测配置不借用新面积。

`recipe.scalar_execution` 仅有一份 1600 位迭代 Keccak 状态，固定块直接装载。SLH 链的中间结果直接反馈；XMSS 使用标量 value/key/mask 寄存器完成复合哈希。P1 batch 接口返回无效和零计数，没有上下文数组、槽位仲裁或批量回写。64 位流式生产复用原有 128 位吸收暂存；读地址仍提前送入端点 RAM。

executor 的 P1 链、FORS 逐叶计算和 Verify 通过标量请求执行；XMSS L-tree 恢复标量二元归约及奇数尾搬移。继续使用共享工作区、20 位叶索引、标准 SHAKE256 配方和完整认证路径重算。模块外部端口、ROM 编码和输出格式不变。

P>1 保留统一上下文与流水执行，recipe 多槽主体有效词法 token 与基线一致。executor 的批量入口新增 `PIPELINE>1` 常量条件；新增标量 L-tree 状态只在 P1 可达。多槽周期是否保持相同仍由本轮完整 Sign 测量核对。

本轮开始时工作区的 recipe 默认 N 已为32，历史冻结基线默认 N 为16；此项既有差异保持不动。共同核和本轮测试均显式传入 N=32，面积对照不受默认值变化影响。

## 验证口径

正式矩阵对四个配置执行三个目标完整 Sign，逐字节核对输出、签名缓存和 Hash/置换数。扩展回归覆盖 P1U1/P1U2 正常与 SYNTHESIS 视图、十二参数 Verify、h10 q=1/1023 Sign、Keygen、配方地址与填充边界、捕获与输出停顿、统计 64 位进位、截断、复位重放、篡改和异常。h20 只运行 Verify。

P1 不再接收 batch 请求，原 batch 故障注入保留在多槽验证；P1 继续验证标量在途错误。统计与调试受 SYNTHESIS 宏控制；综合报告附综合网表诊断残留审计。最终结果以本页动态表格和源码绑定日志为准。
