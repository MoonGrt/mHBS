# 滚动调度退槽路径优化

本轮以 `timing_diagnostic_20261019_103518` 的 baseline 为起点，只修改 executor 的滚动空槽来源：`roll_free = ~pipe_active`。完成响应先更新已有的活动槽寄存器，该槽下一拍再参加分配；其他空闲槽仍可与响应同拍接受请求。目标是切断“标量请求分类 → 批量响应 → 优先选槽 → 动态 busy 读取 → ready → 状态使能”的长组合链。

未增加寄存器或状态，不修改 recipe 的请求／响应契约及其同拍退槽能力。捕获批次继续按原顺序消费，P1 标量路径保持原实现。仅滚动调度的同槽立即复用可能推迟一拍；反馈流水调度相位也可能随之变化，完整 Job 的周期变化以实测为准，不将请求级估算当作严格上界。

## 基线与失败候选

前一候选通过 executor 的 `pipe_mode` 限定返回信号，功能和周期均通过验证，却导致同为 10 ns 的综合面积从 15,463.375 增至 15,811.375 Slice，WNS 从 3.052 降至 3.023 ns。因此本轮撤回该限定，历史源码、日志和失败结论保留在原实验归档。

本轮复用前一实验 **baseline** 的完成综合结果：common P12U1、10 ns、Vivado 2025.2、xc7a200tffg1156-3、默认时序驱动 OOC、通用 Keccak。复用时核对冻结源码、Tcl、工具版本、约束、面积及路径报告校验。只新启动一个候选综合，每个 Vivado 两线程；超过十分钟只延后分析，不终止任务。
