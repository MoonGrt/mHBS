Read-only review of descriptor and 192-bit source-window retiming, plus delayed initial capture.

No functional defect identified in the reviewed revision.

1. Tag reservation and descriptor lifetime. reserve_block consumes need_block and latches format_tag before DESCRIBE. Each slot has at most one outstanding block. A compression return cannot be simultaneously selected by the old need_block mask; its new request is visible only on the following edge. SEND can reserve another context while compression samples the old tag/CV/buffer on that edge.
2. Endpoint timing. DESCRIBE presents first_list_address while the executor registers RAM addresses. PREPARE gives another cycle before BUILD. BUILD presents the next beat address while list_words keeps the current beat's three words. Source staging only consumes list beats after list_words_valid. This remains valid across consecutive list and non-list beats.
3. Beat lifetime. source_window, masks, alignment, staged_beat and length_beat latch together. beat_pending writes the prior staged beat even on an intervening endpoint fetch. Final staging enters DRAIN; DRAIN commits the final word; only then can SEND assert compression input_valid. The unstaged format_length used for encoded_length stays unchanged through this commit.
4. Delayed initial capture. Allocation writes digest and pending tag. On the following edge matching capture_step/iteration copies digest. complete cannot expose that tag to scalar or held batch outputs until pending clears after the copy. Busy-slot ownership prevents reuse during the pending cycle. Simultaneous retirement/refill remains allocation-last. Reset clears pending and beat_pending, while register data can remain unreset because no valid response exposes it.

Remaining risks for measurement: DESCRIBE still combines context selection and phase/shape-to-input_length/packed_address decoding; the compression input CV bank remains asynchronous ahead of the primitive's fresh-input prefix CPA. Added descriptor/beat stages increase cycles per submitted block even though steady-state non-list beat cadence is one per cycle. No physical frequency or ATP gain is claimed by this read-only review.
