# K1：SHAKE P1时序修复候选

冻结设计基于 J1，目标先修复 SHAKE P1U1 的150MHz时序退化，并检查共享控制对两个后端的影响。基线失败矩阵 P1U1 WNS=-0.011ns；不得用100MHz诊断宣称频率达标。

- 共享executor：删除三个标量node写回阶段寄存器，将写入放回原状态分支；保留批量node_pipe_first_phase，适用于所有P/U。
- SHAKE标量流：在原有控制登记边沿提前译码节点长度、字偏移、LMS跨节点拼接、前缀及有效字节。端点RAM数据固定切片后并行AND/OR，替代返回数据上的多层格式选择。新增的是小控制寄存器，没有新增节点数据缓存。
- 不改变状态转移、ready/valid、流地址预取和每拍8字节生产；目标周期不变，最终以完整Sign实测核对。保留旧格式化表达式作为仿真参考，逐拍检查最终64位数据等价。

本地配方三项均通过：P1U1正常、P1U2正常、P1U1综合视图，各459个用例。包括全部15种shape、16/24/32字节节点、135/136/137字节填充边界、停顿及Hash/置换计数。该结果不替代executor整核验证。

候选同一次冻结执行两后端P1U1/P4U1/P12U1/P4U2：8点100MHz common诊断、24项完整Sign、36组功能验证。各点自己的诊断和3项Sign、全局功能验证全部通过后才做固定目标布线；U1=6.666ns，U2=10.000ns。要求内部setup/hold、完整路由、零DRC及实际频率均通过。不执行h20完整树，不搜索或降低频率。

首轮160616因调度器等待线程互相通知形成忙循环而终止，属于基础设施故障；同一RTL修复调度后以本轮重跑。原运行、冻结输入与日志保留，详见RETRY_PROVENANCE.json。

面积、周期与ATP结论等待冻结候选实测；缺失项目留空。后台报告每60秒刷新，全部结束后退出。

## 实测取舍

SHAKE P1U1在6.666ns下布线WNS=-0.052ns、WHS=+0.133ns、DRC=0，布线面积5499.375 Slice；较J1失败矩阵5336.125 Slice增大且未闭合，本候选不选用。其余任务继续后台以保存完整证据，工作RTL已进入K2独立候选。
