# SHA2 G：硬频率约束下的输入与反馈重构

G1 冻结源码：`1130a3a0f81046f662ea6cf8dc1514376178a58decab6e745f6846958426f2b2`。仅修改 SHA2 recipe 和 SHA256 原语，其余八份 RTL 与 E2 一致。保持外部模块端口、合法 P/U、P 个上下文及单 Hash lane；不运行 h20 完整 Keygen/Sign。

本轮以 U1≥150MHz、U2≥100MHz 为硬指标。U1 约束写为 6.666ns，U2 写为 10.000ns；实际周期必须不大于 `1000/目标MHz`，周期验收容差为零。旧 6.667ns 的标称150MHz结果作为历史参考，不计硬通过。14 点必须使用同一份冻结 RTL，逐点完成完整布线、setup/hold、DRC 后验收。

## RTL 改动

1. SHA256 的 H/K/W 预计算保存为64位 carry-save 对，消除 F1 在新块注入前引入的额外进位传播加法。前 min(U,4) 轮使用通用数据依赖，其余展开轮保持普通计算；核心周期、标签、尾轮及停顿行为不变。
2. 单条请求寄存记录在握手时立即占用现有标签，下一拍从已登记字段分配上下文。pending 时不再接受新请求，复位清除占用；完成结果在数据与捕获写好后才可见。该记录不增加额外执行上下文。
3. DESCRIBE 登记256位压缩输入CV，切断“标签选择CV银行→轮运算”路径，不增加第二套512位块缓存。
4. PREPARE 依据已登记的长度和块号产生最后块标志，移除“阶段选择→长度译码→比较→跨槽元数据写回”的串联。

保留 F1 的调度/描述符分级和192位拍暂存。相对 F1，独立标量配方增加1拍；固定旧原语的满槽测试每组整体增加2拍。完整 Sign 的周期由新源实测记录，不能用组件测试或块数推算。

## 验证与证据

原语正常/SYNTHESIS共60组、每组181个独立向量通过，周期/停顿/标签事件与 E2/F1 一致。配方隔离组件通过690个向量、96个批量请求、432个满槽请求、30个零步捕获及接收中复位重放；其固定旧原语，不冒充组合源码验证。

G1组合冻结另通过 P12/P24 正常/SYNTHESIS 12组、432请求全部返回，实际满槽占用、捕获保持、乱序及同拍补发均核对。整源另运行42项完整Sign和36组功能验证，各日志和向量绑定本次源码。
