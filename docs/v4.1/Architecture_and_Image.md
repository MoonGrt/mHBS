# μHBS v4.1：共同硬件与独立镜像

工程版本 **v4.1**，指令 ABI **4**。V3 与 V4 原始证据保持归档。

## 执行流程

执行器保留 **HASH / CHAIN / TREE / TRANSFORM / EMIT** 五类宏指令。
program 指定宏操作顺序、SINGLE/RUN/LOOP/HALT 与入口；template 提供命令；
descriptor 指定配方、参数及结果路由。FSM 完成宏内部迭代、存储访问和 lane 调度。
七种参数点均由镜像驱动同一个执行器，不增加按算法选择的完整 Keygen/Sign FSM。

`uhbs_top` 的输入只有 `clk`、高有效 `rst`。复位异步置位、两级同步释放。

复位释放 → 校验三个镜像 → 装载 Job → Keygen → 从 program 读取消息 → Sign → 停机。

`done` 或 `error` 保持到复位。每次复位最多一次签名。`out_valid` 指示当拍结果，
`out_keep` 指示 `out_data[63:0]` 的有效字节，最低字节先输出；无反压。
`result_kind=0/1` 分别表示 Keygen/Sign；`out_last` 表示对应输出的最后一拍。
`boot_cycles` 单列镜像校验与装载成本，`keygen_cycles`、`sign_cycles` 包括操作中的 ROM 访问。
Hash/置换计数在每个操作开始时清零；在 `keygen_done` 和 `done` 处分别采样。

`u2_bootall` 将 program、template、descriptor 的逐字校验分别寄存后消费，
每个扫描末尾多一拍排空流水；有效标志阻止前一阶段或复位中的值误触发错误。
Boot 从 `u2_stream64` 的 259 拍变为 262 拍，七点 Keygen/Sign 周期和计数不变。
独立边界单测故意破坏 program[63]、template[63]、descriptor[127]，
确认最后一字仍在释放执行核前被拒绝。

`make architecture-test` 使用七个短程序检查顺序、模板、配方、路由、循环和 RUN 展开；
软件模型先运行，再逐条比对 RTL 接受的宏命令及全部输出，Hash 输出另有 hashlib 独立校验。
这些是架构检查，完整算法正确性仍由七点 Keygen/Sign KAT 验证。

## 三个独立 ROM

| ROM | 逻辑容量 | 当前物理容量 | 逻辑读取延迟 | 内容 |
|---|---:|---:|---|---|
| program | 64 × 128 bit | 64 × 128 bit | 组合读取，消费者在时钟沿采样 | 指令、Job、消息 |
| template | 64 × 128 bit | 64 × 64 bit | 同上；固定连线展开 | 操作模板 |
| descriptor | 128 × 64 bit | 128 × 64 bit | 同上 | 参数、配方、树操作、路由 |

descriptor 使用两个读取端口，通过物理存储复制实现；复制存储计入总面积。
两个端口按控制状态复用；端口缩减候选本身不增加执行周期。另有 `LOAD_DESCRIPTOR` 寄存候选，
每个宏操作增加一拍，目的是切断 ROM 到译码路径。是否保留以候选面积、周期和时序证据决定。
`.mem` 每行一个十六进制逻辑字。Job/消息字节按低位到高位排列。
算法定义的大端整数编码由配方单独处理。
template 的物理压缩只在 INIT 生成和 ROM 展开处处理，逻辑 `.mem` 仍为 128 位。
保留字段、非法值检查以及 descriptor 压缩淘汰记录见 [面积优先优化](Area_Optimization.md)。

| program 地址 | 内容 |
|---|---|
| 0–31 | ABI 4 指令；有效区后的字必须为零 |
| 32–33 | secret seed，32 字节槽 |
| 34–35 | secret PRF，32 字节槽 |
| 36–37 | public seed，32 字节槽 |
| 38–39 | randomizer，32 字节槽 |
| 40 | identifier，16 字节 |
| 41 | 控制字段，见下表 |
| 42–43 | 保留为零 |
| 44–49 | 1–87 字节消息，尾部填零 |
| 50–63 | 保留为零 |

| 控制字 41 位段 | 含义 |
|---|---|
| 10:0 | 初始索引 q |
| 17:11 | 消息字节数 |
| 23:18 | 有效 program 指令数，1–32 |
| 30:24 | 有效 template 数，1–64 |
| 127:31 | 保留为零 |

短于 32 字节的节点槽高位填零。SINGLE/RUN/LOOP/HALT 原编码不变；
入口保留在 descriptor 0，profile 在 descriptor 1。指令禁止进入 Job/消息区。

## 为什么替换镜像不会改变面积

处理器先以通用 ROM 数据端口独立综合，不提供任何算法或初始化常量。
ROM 与复位适配器独立综合，再链接处理器检查点。ROM 使用固定容量分布式存储原语，
初始化内容在实现后修改；不会通过重新综合把内容传播到处理器。
七个镜像共用节点宽度 32 字节、摘要宽度 49 字节、133 条链的硬件容量。
`LANES`、`UNROLL` 是共同硬件候选参数，七个镜像必须使用同一个取值。

验收需证明七份检查点除 ROM INIT 外，单元、连接、位置、布线均一致，
并使用一个共同面积和一个共同频率计算七组 ATP。仅源码相同不能证明面积相同。

## 当前数据通路候选

端点存储固定为 128 项主区加 8 项尾区，合法索引仍为 0–132；保持奇偶 bank 和双 lane 写入。
FORS 根使用单写、相邻双读分布式存储。有状态认证路径仅缓存选定 q 的路径，不缓存完整树。

`u2_stream64` 复用一套 64 位流式格式器，每两拍组成一个原有 128 位吸收输入。
136 字节块的最后一拍只含 8 字节，高半字清零。短 Hash 使用完整块快速装载，
SLH 链反馈复用该格式器并直接进入下一轮置换，不经过流式装载。
这种改动增加部分长列表/消息 Hash 的周期，报告采用实际仿真周期，不沿用旧周期。

面积优先候选 `u2_area_stream32` 将长消息格式器进一步缩至 32 位，
继续保留短 Hash 与链反馈快速路径；另一组合候选 `u2_area_balanced` 保持 64 位格式器。
两者均采用共享的 128 位吸收 XOR、单宏发射和单完成事件，以及 template 物理压缩。
program 的顺序、两级 LOOP、RUN 和五类宏能力保留。单宏调度与双 Hash lane 属于不同层级；
前者裁剪不取消宏内部的双 lane 并行。

## 固定索引基准语义（当前阶段）

当前工程策略为 `index_policy=fixed_q_no_guard`。XMSS/LMS 的 Keygen 与 Sign
均使用镜像中的 q（0–1023），签名后不递增、不记录索引消耗状态。
认证路径必须有效且属于相同 q；1024 是非法输入，不表示本阶段存在耗尽状态机。
当前顶层不提供 `state_next_q`，内部不实现索引预留、提交握手或防复用 guard。
完成或错误后停机至复位，复位允许重放固定向量。

这是无索引保护的固定向量性能基准。历史带 guard 的报告和源码快照保持归档；
面积及周期对比必须同时说明索引策略不同。当前优化固定 U2、双 lane，
保留三个独立分布式 ROM，不再对 U4 执行新的综合或布线。

## 软件先行证据

`manifests/experiments/unified_hbs_v4.1/software_gate.json` 封存模型与测试源码哈希。
软件门禁通过后才修改 RTL。解释器仅从三个镜像解码 Job、消息和算法配置，
检查完整输出、Hash 输入输出序列、计数、缓存和索引状态；原独立模型/KAT 测试同时运行。

## 比较边界

与论文的比较为 **NON_STRICT**：SLH-DSA 与论文 SPHINCS+ 的版本不同；
LMS 使用 SHAKE256/256 研究 profile；消息和密钥是固定向量；状态算法采用选定路径缓存。
v4.1 的共同最大容量硬件与 V3/V4 的分别静态综合面积含义不同。
实际资源与周期、时序及 ATP 是否通过，必须以验收报告的已完成证据为准。
